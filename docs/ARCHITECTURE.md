# Architecture

One Next.js app (pages, server actions, API routes) and one background worker, sharing PostgreSQL (with pgvector), Redis (BullMQ) and a file storage volume. Both run from the same Docker image.

```
browser ──> web (Next.js, port 3000) ──> PostgreSQL + pgvector   (all data, brand_id on every brand table)
                 │                    └─> storage volume          (brands/<brandId>/...)
                 └─ jobs ──> Redis/BullMQ ──> worker ──> Anthropic API (text), fal.ai (images), Chromium (rendering)
```

## Brand isolation

Every brand table has `brand_id`. Code reaches brand data only through `BrandScope` (`src/lib/brands/scope.ts`), which adds the brand filter to every select, update and delete and sets it on every insert. Files are stored under `brands/<brandId>/`, and file routes check the key belongs to the brand in the URL. Prompts are built from the scoped Brand Brain only. Tests prove that no fact, prompt, file, post or export of one brand reaches another (`tests/acceptance.test.ts`).

## Jobs

Everything slow or paid runs as a job (`jobs` table + BullMQ): document ingestion, plan generation, batch production, rendering, regeneration. A batch starts as `awaiting_confirmation` with a cost estimate and only runs after the operator confirms it. Handlers are idempotent: they skip work already in the database, so a job that crashed or was killed resumes without duplicates (master posts are unique per plan item). On start, the worker re-queues jobs the database still marks queued or running.

## AI roles

Each role has a versioned prompt in `prompts/` (frontmatter `version`, `## System`, `## User`). `runRole` (`src/lib/ai/run.ts`) fills the prompt, asks for JSON that matches a Zod schema (structured output), validates it, retries up to three times with the validation error as feedback, and logs every attempt with tokens, cost and duration to `ai_runs` and `usage_records`.

Roles: Brand Brain extractor, Strategist, Copywriter (master post and platform copy), Visual Director, Video Producer (storyboards), Creative Director (scores and flags). A rule-based claim guard (`src/lib/posts/claims.ts`) runs next to the Creative Director and flags any number, superlative, certification, health or price claim not found in the approved Brand Brain.

## Rendering

Two layers: a background (generated by the image provider, an approved brand photo, or plain brand colour) and an HTML/CSS layout with the post's text, brand colours, fonts and logo, rendered to PNG with Playwright Chromium at the platform's exact size. Chromium may only load data: URLs and Google Fonts while rendering. Storyboards are text and are never rendered or called videos.

## Export

`src/lib/export/export.ts` packs approved posts into a ZIP with per-date, per-platform folders, a Metricool bulk CSV and a generic CSV. Format: `docs/EXPORT.md`.
